# Introduction

## Aims
This tutorial takes the form of a brief hands-on course showing how to process and analyse sequencing data using the [MetaCentrum NGI](https://www.metacentrum.cz/en/index.html) (National Grid Infrastructure). Participants will be introduced to the basics of using MetaCentrum, including how to [log in to the frontend server](https://docs.metacentrum.cz/en/docs/access/log-in), [manipulate data](https://docs.metacentrum.cz/en/docs/data/large-data), [start an interactive or batch job](https://docs.metacentrum.cz/en/docs/computing/run-basic-job), and [install applications](https://docs.metacentrum.cz/en/docs/software/install-software) locally.

In the practical section of the course, we will analyse private (unpublished) [Oxford Nanopore Technologies](https://nanoporetech.com/) (ONT) data from a pilot project investigating the distribution of methylation sites in the genome of [_Haemonchus contortus_](https://en.wikipedia.org/wiki/Haemonchus_contortus), a gastrointestinal parasite of small ruminants. Unfortunately, processing raw ONT reads, basecalling and working with modified bases often require considerable hardware resources and time-consuming tuning to find the optimal parameters. To speed up the course, we will use a reduced input dataset and mostly default parameters during data processing.

> [!IMPORTANT]  
> **The aim of this course is not to create a perfect ONT data processing pipeline.**
> 
> Due to the time limitations of this course and its primary focus on using grid infrastructure as effectively as possible, we will carry out a few basic steps on a small sample of ONT genomic reads. The aim is to identify modified bases (e.g., methylated bases).

> [!NOTE]
> Throughout this tutorial, important points are supplemented with links to more detailed descriptions and explanations in the [documentation](https://docs.metacentrum.cz/en/docs/welcome).

## Dedicated resources

As is typical for grid computing, submitted jobs are sorted into specific [queues](https://docs.metacentrum.cz/en/docs/computing/concepts#queues), mainly based on the amount of requested resources. The delay between job submission and the start of the calculation is determined by the combination of the required resources and the current infrastructure load. Very demanding jobs may have to wait several days in the queue before all the necessary resources become available. To avoid this, we will use a [special queue](https://metavo.metacentrum.cz/pbsmon2/queue/MetaSeminar@pbs-m1.metacentrum.cz) reserved exclusively for this course, `MetaSeminar`. This queue uses the [zenon1.cerit-sc.cz](https://metavo.metacentrum.cz/pbsmon2/machine/zenon1.cerit-sc.cz) and [zenon2.cerit-sc.cz](https://metavo.metacentrum.cz/pbsmon2/machine/zenon2.cerit-sc.cz) compute nodes, each with 32 AMD EPYC 7351 CPU cores (2x16), 504 GB RAM and 2 TB SSD + 2 TB HDD scratch discs.

> [!IMPORTANT]  
> Each job submitted during this course must be sent to this dedicated queue. As you will see later, interactive jobs will include the parameter `-q MetaSeminar`, while batch jobs will include the line with `#PBS -q MetaSeminar`. The [PBSPro](https://docs.metacentrum.cz/en/docs/computing/concepts#pbs-server) job scheduler will send jobs to this specified queue in both cases.

# Log in to the frontend server

Like most computing and data centres, MetaCentrum's compute nodes run exclusively on Linux (OS [Debian](https://www.debian.org/)) and are primarily controlled via the command line.  Linux is favoured for its stability, security, speed, adaptability and compatibility. Furthermore, advanced scientific software tools are mainly designed and optimised for Linux.

> [!IMPORTANT]  
> MetaCentrum does not offer the OS Windows and its applications.

We will use one of the login servers, known as the [frontend](https://docs.metacentrum.cz/en/docs/computing/infrastructure/frontend-storage), to log in. [These servers](https://docs.metacentrum.cz/en/docs/computing/infrastructure/frontends) are accessible via SSH and serve as the main gateway to the entire infrastructure.

> [!WARNING]
> Frontend servers are virtual machines with limited computational power. They are primarily used for basic data inspection and manipulation, preparing shell scripts for batch jobs and short compilations. Do not use them for long or demanding calculations :pray:; use an [interactive job](https://docs.metacentrum.cz/en/docs/computing/run-basic-job#interactive-job) instead.

> [!IMPORTANT]
> Long and demanding calculations running directly on frontend servers are terminated automatically.

> [!NOTE]
> MetaCentrum can be accessed worldwide. We do not implement any geoblocking.

The following diagram illustrates the position of the frontend servers (labelled as **Login nodes**) within the grid infrastructure. [This page](https://docs.metacentrum.cz/en/docs/computing/infrastructure/frontends) lists all accessible frontend servers.

> The system variable USER (`$USER`) is set automatically after logging in and contains the real username.

> [!IMPORTANT]  
> MetaCentrum does not fully support traditional authentication with SSH keys for log in. 
>
> MetaCentrum uses the [Kerberos](https://docs.metacentrum.cz/en/docs/access/log-in#kerberos) system for authentication, which requires a **username** and **password**.

> [!TIP]
> Kerberos is available for all operating systems and can be [installed and configured](https://docs.metacentrum.cz/en/docs/access/security/kerberos#install-kerberos) on your personal computer. This allows you to generate a local Kerberos ticket with a lifetime of up to 24 hours, allowing you to log in to Metacentrum nodes without entering your password for this period.

Windows OS users can use an SSH client such as PuTTY ([as described here](https://docs.metacentrum.cz/en/docs/software/graphical-access#connect-with-putty-in-windows)). Newer versions of OS Windows have a built-in OpenSSH client. ```shell


# System of software modules 

The software tools available in MetaCentrum are accessible via [environment modules](https://modules.readthedocs.io/en/stable/index.html#). This system simplifies the precise and controlled use of different software. Each program (and each version, eventually with additional modifications) is prepared as an individual module that must be activated (loaded) before use. This modifies the user's environment, setting everything necessary for the program to run, especially the `$PATH` and `$LD_LIBRARY_PATH` variables and dependencies.

> [!TIP]
> How to work with MetaCentrum modules is described in detail [here](https://docs.metacentrum.cz/en/docs/software/modules).

> [!IMPORTANT]  
> MetaCentrum provides several thousand modules. With so many modules, manual control is no longer possible, and occasionally things do not work perfectly. If you experience any issues, please email us at meta@cesnet.cz.

> [!IMPORTANT]  
> As MetaCentrum provides hundreds of tools, it is not possible to keep all of them up to date. If you require a newer version of a tool or any new tool in general, please email us at meta@cesnet.cz. However, we encourage users to [install the tools themselves](https://docs.metacentrum.cz/en/docs/software/install-software), and we are available to assist with this process.

We can run a few commands and explain how the module system works. Let's try loading a module for [BLAST+](https://blast.ncbi.nlm.nih.gov/doc/blast-help/downloadblastdata.html#downloadblastdata).

```shell
module ava blast
```
```shell
module ava *blast*
```
```shell
module ava blast-plus/
```
```shell
module add blast-plus/2.16.0-gcc
```
```shell
module list
```
```shell
module rm blast-plus
```
```shell
module list
```
> [!WARNING]  
> Remember that activating a module will modify your environment in some way. Loading too many modules in a single session can lead to conflicts, resulting in some applications not functioning correctly. The module that could conflict with others can only be reliably limited to specific parts of the job.

> [!IMPORTANT]  
> The command `module rm` may not always undo all the changes to the environment.

```shell
( module add module_name_1
programme_1 < in_1 > out_1
)
# After the right-round bracket, the used module is inactive, and all environmental modifications are suppressed. Another module can then be safely loaded.
module add module_name_2
programme_2 < in_2 > out_2
```

# Convert the FAST5 files to the POD5 format

FAST5 files are based on the [HDF5 format](https://www.hdfgroup.org), which makes them large and slow to process. This makes them unsuitable for modern ONT workflows. Converting them to the newer [POD5 format](https://software-docs.nanoporetech.com/pod5/latest/), which is built on [Apache Arrow](https://arrow.apache.org/), significantly improves read/write speeds and reduces file size while enabling efficient parallel access. POD5 is faster and more storage-efficient than FAST5 and is fully supported by the latest ONT tools, such as [Dorado](https://software-docs.nanoporetech.com/dorado/latest/).

In this part of the course, we will install the POD5 python package and convert the FAST5 files to the POD5 format.

The methodology will include the following steps:
- starting an [interactive job](https://docs.metacentrum.cz/en/docs/computing/run-basic-job#interactive-job) with [scratch storage](https://docs.metacentrum.cz/en/docs/computing/infrastructure/scratch-storages).
- installing the POD5 python package.
- converting the FAST5 files to POD5 format.

> [!IMPORTANT]  
> We encourage users to [install the tools themselves](https://docs.metacentrum.cz/en/docs/software/install-software), and we are available to assist with this process.

Firstly, we will submit the [interactive job](https://docs.metacentrum.cz/en/docs/computing/run-basic-job#interactive-job). The meaning of the individual parts of the command is explained below.

```shell
qsub -I -l select=1:ncpus=1:mem=10gb:scratch_ssd=20gb -l walltime=1:00:00 -q MetaSeminar
```

| Parameter | Action |
| ------------- | -------------|
| `qsub` | Command that submits jobs. |
| `-I` | Declares that	the job	is to be run interactively. |
| `select=1` | Reserves resources on one physical node. |
| `ncpus=1` | Reserves two processors (threads). |
| `mem=10gb` | Reserves 10 GB of RAM. |
| `scratch_local=20gb` | Reserves 20 GB of disk space on scratch. |
| `walltime=1:00:00` | Reserves one hour for the job. |
| `-q MetaSeminar` | Submits the job to the MetaSeminar queue. |

> [!TIP]
> The qsub command, with its most essential parameters, can be [assembled online](https://metavo.metacentrum.cz/pbsmon2/qsub_pbspro).

# Basecalling

Basecalling of ONT reads in POD5 format using the [Dorado](https://software-docs.nanoporetech.com/dorado/latest/) basecaller is essential, as the raw signals generated by the nanopore sequencer represent changes in electrical current rather than actual nucleotide sequences. Dorado is ONT’s most recent and accurate basecaller. It utilises advanced neural network models to translate the raw signal traces stored in POD5 format into nucleotide sequences with associated quality scores. Basecalling of POD5 ensures faster processing, better compression, and improved data handling compared to the older FAST5 format. This leads to higher accuracy, reduced storage requirements and compatibility with ONT’s modern analysis pipelines.

In this part of the course, we will carry out basecalling of ONT reads using a genomic reference. The methodology will include the following steps:
- download the _H. contortus_ reference genome from the [WormBase Parasite](https://parasite.wormbase.org/Haemonchus_contortus_prjeb506/Info/Index/) database.
- use the suitable version of the [Dorado basecaller](https://software-docs.nanoporetech.com/dorado/latest/).
- preparation of a shell script for a [batch job](https://docs.metacentrum.cz/en/docs/computing/run-basic-job#batch-job-example).

Open this file in the nano text editor using the command `nano nimh_course/dorado_basecalling.sh` and then paste the entire script below into it:

```shell
#!/bin/bash
#PBS -N dorado_basecall
#PBS -l select=1:ncpus=32:mem=480gb:scratch_ssd=100gb
#PBS -q MetaSeminar
#PBS -l walltime=6:0:0

# Test whether a scratch directory exists.
# The variable SCRATCHDIR is set automatically.
test -n "$SCRATCHDIR" || { echo >&2 "Variable SCRATCHDIR is not set!"; exit 1; }

# The scratch directory should be cleaned automatically.
trap "clean_scratch" TERM EXIT

# Redirect all potential temporary files to the scratch directory.
export TMPDIR=$SCRATCHDIR

# Copy the input files to the scratch directory.
scp storage-plzen1.metacentrum.cz:nimh_course/converted_reads.pod5 $SCRATCHDIR
scp storage-plzen1.metacentrum.cz:nimh_course/dorado_0.9.1.tar.gz $SCRATCHDIR
cp /storage/plzen1/home/$USER/nimh_course/haemonchus_contortus.PRJEB506.WBPS19.genomic.fa $SCRATCHDIR
cp -r /storage/plzen1/home/$USER/nimh_course/dna* $SCRATCHDIR

# Navigate to the scratch directory.
cd $SCRATCHDIR

# Extract the Dorado archive.
tar -xzf dorado_0.9.1.tar.gz

# Set the necessary paths and load the dependency module.
export PATH=$SCRATCHDIR/dorado_0.9.1/bin:$PATH
export LD_LIBRARY_PATH=$SCRATCHDIR/dorado_0.9.1/lib:$LD_LIBRARY_PATH
module add minimap2/2.22 || { echo >&2 "Module load failed!"; exit 2; }
unset CUDA_VISIBLE_DEVICES

# Start Dorado.
dorado basecaller dna_r9.4.1_e8_sup@v3.3 converted_reads.pod5 -v --min-qscore 5 --trim all \
--reference haemonchus_contortus.PRJEB506.WBPS19.genomic.fa --modified-bases 5mCG_5hmCG > dorado_basecalled_mapped_batch_job.bam

# Copy the final result back to storage.
scp dorado_basecalled_mapped_batch_job.bam || export CLEAN_SCRATCH=false
```

| Parameter | Action |
| ------------- | -------------|
| `basecaller` | Run the basecalling pipeline. |
| `dna_r9.4.1_e8_sup@v3.3` | Model version. |
| `converted_reads.pod5` | Name of the input file. |
| `-v` | Print more details about the run. |
| `--min-qscore 5` | Discard reads with mean Q-score below this threshold. |
| `--trim all` | Trim all detected adapters, primers, and barcodes. |
| `--reference haemonchus_contortus.PRJEB506.WBPS19.genomic.fa` | Name of the reference genome fasta file |
| `--modified-bases 5mCG_5hmCG` | List of analysed modified bases. |
| `dorado_basecalled_mapped_batch_job.bam` | Output file name in BAM format. |
