# Introduction

## Aims
This tutorial takes the form of a brief hands-on course showing how to process and analyse sequencing data using the [MetaCentrum NGI](https://www.metacentrum.cz/en/index.html) (National Grid Infrastructure). Participants will be introduced to the basics of using MetaCentrum, including how to [log in to the frontend server](https://docs.metacentrum.cz/en/docs/access/log-in), [manipulate data](https://docs.metacentrum.cz/en/docs/data/large-data), [start an interactive or batch job](https://docs.metacentrum.cz/en/docs/computing/run-basic-job) and [install applications](https://docs.metacentrum.cz/en/docs/software/install-software) locally.

In the practical section of the course, we will analyse private (unpublished) [Oxford Nanopore Technologies](https://nanoporetech.com/) (ONT) data from a pilot project investigating the distribution of methylation sites in the genome of [_Haemonchus contortus_](https://en.wikipedia.org/wiki/Haemonchus_contortus), a gastrointestinal parasite of small ruminants. Unfortunately, processing raw ONT reads, basecalling and working with modified bases often require considerable hardware resources and time-consuming tuning to find the optimal parameters. To speed up this course, we will use a reduced input dataset and mostly default parameters during data processing.

<p align="center"><img src="https://upload.wikimedia.org/wikipedia/commons/5/55/Haemonchus_contortus_%28YPM_IZ_101907%29.jpeg"></p>

> [!IMPORTANT]  
> **The aim of this course is not to create a perfect ONT data processing pipeline.**
> 
> Due to the time limitations of this course and its primary focus on using grid infrastructure as effectively as possible, we will carry out a few basic steps on a small sample of ONT genomic reads. The aim is to identify modified (methylated) bases.

> [!NOTE]
> Throughout this tutorial, important points are supplemented with links to more detailed descriptions and explanations in the [documentation](https://docs.metacentrum.cz/en/docs/welcome).

## Prerequisites

To get the most out of this course, each participant should
  -  **be a registered MetaCentrum user** (due to the account approval and creation process, applications must be submitted no later than one day before the start of the course).
  -  **know the login information** (username and password, created during the application process).
  -  **have a laptop/PC with a working internet connection.**
  -  **be able to log in to the remote server via the SSH protocol.**
  -  **know how to use the command line interface (CLI)**, recommended.
  
> [!NOTE]
> This course is designed for participants without strong command line knowledge. However, some basic knowledge is recommended. All commands and shell scripts used during the course can be found below and copied directly.

> [!NOTE]
> No data or software tools need to be downloaded or installed by participants before the course. Data will be downloaded during the course, and all software tools (which are freely available for non-commercial use) are already accessible to MetaCentrum users. If not, we will install them.

## Dedicated resources

As is typical for grid computing, submitted jobs are sorted into specific [queues](https://docs.metacentrum.cz/en/docs/computing/concepts#queues), mainly based on the amount of requested resources. The delay between job submission and the start of the calculation is determined by the combination of the required resources and the current infrastructure load. Very demanding jobs may have to wait several days in the queue before all the required resources are free. To avoid this, we will use a special queue reserved exclusively for this course, `MetaSeminar`. This queue uses the [zenon60.cerit-sc.cz](https://metavo.metacentrum.cz/pbsmon2/machine/zenon60.cerit-sc.cz) compute node with 32 AMD EPYC 7351 CPU cores, 512 GB RAM and 2 TB SSD + 2 TB HDD scratch discs. 

> [!IMPORTANT]  
> Each job submitted during this course must target this dedicated queue. As you will see later, interactive jobs will include the parameter `-q MetaSeminar`, while batch jobs will include the line with `#PBS -q MetaSeminar`. The job scheduler [PBSPro](https://docs.metacentrum.cz/en/docs/computing/concepts#pbs-server) will send jobs to this specified queue in both cases.

# Log in to the frontend server

Like most computing and data centres, MetaCentrum's compute nodes run exclusively on Linux (OS [Debian](https://www.debian.org/)) and are primarily controlled via the command line.  Linux is favoured for its stability, security, speed, adaptability and compatibility. Furthermore, advanced scientific software tools are primarily designed and optimised for Linux.

> [!IMPORTANT]  
> MetaCentrum does not offer the OS Windows and its applications.

We will use one of the login servers, known as the [frontend](https://docs.metacentrum.cz/en/docs/computing/infrastructure/frontend-storage), to log in. [These servers](https://docs.metacentrum.cz/en/docs/computing/infrastructure/frontends) are accessible via the SSH protocol and act as the main gateway for the entire infrastructure.

> [!WARNING]
> Frontend servers are virtual machines with very limited computational power. They are primarily used for basic data inspection and manipulation, preparing shell scripts for batch jobs and short compilations. Do not use them for long or demanding calculations :pray:; use an [interactive job](https://docs.metacentrum.cz/en/docs/computing/run-basic-job#interactive-job) instead.

> [!IMPORTANT]
> Long and demanding calculations running directly on frontend servers are terminated automatically.

> [!NOTE]
> MetaCentrum can be accessed worldwide. We do not implement any geoblocking.

The following diagram illustrates the position of the frontend servers (labelled as **Login nodes**) within the grid infrastructure. [This page](https://docs.metacentrum.cz/en/docs/computing/infrastructure/frontends) lists all accessible frontend servers.

<p align="center"><img src="https://tacc.github.io/ctls2017/resources/hpc_schematic.png"></p>

In the following tutorial, we will use the `nympha` frontend with the address `nympha.metacentrum.cz` to log in. Nympha runs on Debian 12, and the home directory is mounted on the `plzen1` storage (accessible as `/storage/plzen1/home/$USER/`). However, any other standard frontend server can also be used. They all have the same functionality.

> [!NOTE]  
> The system variable USER (`$USER`) is set automatically after logging in and contains the real username.

> [!IMPORTANT]  
> MetaCentrum for log in does not fully support traditional authentication with SSH keys. 
> MetaCentum uses the [Kerberos](https://docs.metacentrum.cz/en/docs/access/log-in#kerberos) system for authentication, which requires a **username** and **password**.

> [!TIP]
> Kerberos is available for all operating systems and can be [installed and configured](https://docs.metacentrum.cz/en/docs/access/security/kerberos#install-kerberos) on your personal computer. This enables you to generate a local Kerberos ticket with a lifetime of up to 24 hours, allowing you to log in to Metacentrum nodes without entering your password for this period.

Windows OS users can use an SSH client such as PuTTY ([as described here](https://docs.metacentrum.cz/en/docs/software/graphical-access#connect-with-putty-in-windows)). Newer versions of OS Windows have a built-in OpenSSH client. Command-line interface (CLI) users can open their terminal and type the following command, replacing `user_name` with their actual MetaCentrum username, followed by their password.

```shell
ssh user_name@nympha.metacentrum.cz
```

> [!NOTE]  
> No characters appear when typing a password into the terminal. This is standard security behaviour.

> [!IMPORTANT]  
> **Never share your MetaCentrum password with anyone else.** This could be seen as a breach of the terms of use, which could result in your account being banned.

# Basic orientation in your home directory

In Metacentrum, the visual interface found on desktop computers is usually lacking. Instead, we use text commands. The following table shows a few commands for basic work with the Linux command line. We will use most of these commands further on in the course.

> [!TIP]
> There are hundreds of other commands. You can find more comprehensive tutorials on this topic online, such as this [one](https://www.freecodecamp.org/news/the-linux-commands-handbook/).

| Command | Action |
| ------------- | -------------|
| `.` or `./`  | Refers to the present location. |
| `..` or `../` | Refers to the parent directory. |
| `cat` | Prints the entire content of a file. |
| `cd` | Changes the working directory. |
| `cp` | Copies files. |
| `cp -r` | Copies files and directories with their contents. |
| `head` | Prints the first ten lines of a file. |
| `less` | Prints a file's contents one screen at a time. |
| `ls` | Lists a directory's contents. |
| `ls -lh` | Lists a directory's contents in a columnar, human-readable format. |
| `mkdir` | Creates a new directory. |
| `nano` | Opens a lightweight text editor. |
| `mv` | Moves or renames files and directories. |
| `pwd` | Prints the path of the current working directory. |
| `rm` | Removes a file. |
| `rmdir` | Removes an empty directory. |
| `rm -r` | Removes the directory and its content. |
| `scp` | Transfers data. |
| `ssh` | Provides a secure, encrypted connection between two hosts over an insecure network. |
| `touch` |  Creates an empty file. |

> [!TIP]
> The CLI is not the only way how to use MetaCentrum. Also, GUI access and applications are available. For example, the [Open OnDemand](https://docs.metacentrum.cz/en/docs/ondemand) service, [virtual network computing](https://docs.metacentrum.cz/en/docs/software/graphical-access) or the [Rancher/Kubernetes](https://docs.cerit.io/) platform.

Once you have successfully logged in via the command

```shell
ssh user_name@nympha.metacentrum.cz
```

you then will be taken to your home directory by default. You can use the `pwd` command to display the absolute path to your current location in the system.

```shell
pwd
```

The files and directories you can see, access and use depend on your current location, i.e. where you are in the system. Use the `ls` command to see what files and directories are available at your current location, i.e. in your home directory.

```shell
ls
```

We can create a new directory named `test_directory`. If you do not like this name, you can choose a different one :wink:.

```shell
mkdir test_directory
```

Once the `test_directory` folder has been created, run these two commands and compare what was printed in the terminal.

```shell
ls
```
```shell
ls -l
```

> [!NOTE]  
> The terms **folder** and **directory** are interchangeable.

We will also need to edit text files, specifically the shell scripts for the batch jobs. We can use the `touch` command to create an empty file. Let's call this file as `test_file.txt`.

```shell
touch test_file.txt
```

You can then run the `ls` or `ls -lh` command again (depending on your preference) to check whether the file `test_file.txt` was created successfully.

Let's use the text editor [nano](https://www.nano-editor.org/) to open and further edit the text file `test_file.txt`. 

```shell
nano test_file.txt
```

> [!TIP]
> Use the `tab` key to autocomplete file or folder names. 

> [!NOTE]  
> Metacentrum also offers other editors, such as `vi`, `vim` and `mcedit`. 

You can start typing text as soon as the `nano` editor is open. When you have finished, press the keys `ctrl` and `x` simultaneously. You will then be asked if you want to save the changes (`Save modified buffer?`). Press `y`, then press the `enter` key to overwrite the original file `test_file.txt`.

To print the contents of the text file in the terminal, use the `cat` command.

```shell
cat test_file.txt
```

> [!WARNING]
> The `cat` command prints the entire contents of a file to the terminal all at once. Therefore, it is not suitable for viewing very long text files. A better option is the `less` command, which displays a file's contents one screen at a time.

Finally, we can try to rename the file `test_file.txt` to `test_file_renamed.txt` and move it into the directory `test_directory`.

> [!NOTE]  
> Remember that the `mv` command can rename and move files and folders.

```shell
mv test_file.txt test_file_renamed.txt
```
```shell
mv test_file_renamed.txt test_directory
```

In the final step of this chapter, we can check whether the renamed file `test_file_renamed.txt` has been moved to the correct location. If so, we can delete the `test_directory` folder and its content, as we will have no further use for them. 

```shell
ls test_directory
```
```shell
rm -r test_directory
```

# System of software modules 

The software tools available in MetaCentrum are accessible via [environment modules](https://modules.readthedocs.io/en/stable/index.html#). This system simplifies the precise and controlled use of different software. Each program (and each version, eventually with additional modifications) is prepared as an individual module that must be activated (loaded) before use. This modifies the user's environment, setting everything necessary for the program to run, especially the `$PATH` and `$LD_LIBRARY_PATH` variables and dependencies.

> [!TIP]
> How to work with MetaCentrum modules is described in detail [here](https://docs.metacentrum.cz/en/docs/software/modules).

> [!IMPORTANT]  
> MetaCentrum provides several thousand modules. With such a large number of modules, manual control is no longer possible and occasionally, things do not work perfectly. If you experience any issues, please email us at meta@cesnet.cz.

> [!IMPORTANT]  
> As MetaCentrum provides hundreds of tools, it is not possible to keep all of them up to date. If you require a newer version of a tool or any new tool in general, please email us at meta@cesnet.cz. However, we encourage users to [install the tools themselves](https://docs.metacentrum.cz/en/docs/software/install-software), and we are available to assist with this process.

We can run a few commands and discuss how the module system works. Let's try to load a module for [BLAST+](https://blast.ncbi.nlm.nih.gov/doc/blast-help/downloadblastdata.html#downloadblastdata).

```shell
module ava blast
```
```shell
module ava *blast*
```
```shell
module ava blast-plus/
```
```shell
module add blast-plus/2.16.0-gcc
```
```shell
module list
```
```shell
module rm blast-plus
```
```shell
module list
```
> [!WARNING]  
> Remember that activating a module modifies your environment in some way. Loading too many modules in one session can lead to conflicts, resulting in some applications not functioning correctly. The module that could conflict with others can only be reliably limited to specific parts of the job.

```shell
( module add module_name_1
programme_1 < in_1 > out_1
)
# After the right-round bracket, the used module is inactive, and all environmental modifications are suppressed. Another module can then be safely loaded.
module add module_name_2
programme_2 < in_2 > out_2
```
